# 观点型短视频创作工作流 Skill 设计规范

**状态：** 已确认，首版 MVP

**日期：** 2026-09-01

**Skill 名称：** `short-video-opinion-workflow`

## 1. 产品目标

为单一微信视频号账号建立一套模块化、可追溯、可中断恢复的观点型短视频生产工作流。工作流从热点发现开始，经过证据研究、人工选题、观点脚本、人工审稿、旁白与画面规划、合成质检，最终生成一条可人工发布的竖屏 MP4。

首版服务于流量收益探索，但不承诺流量结果。系统优化的是持续产出、内容可信度、表达质量、版权可追溯和试错效率。

## 2. 已确认的内容定位

- 单一账号、单一工作流，不做多账号矩阵。
- 以生活态度、社会观察、思考和辩论型话题为主。
- 典型开头是有冲突但可被证据回答的问题，例如：“为什么媒体集中关注某个人？他真正值得讨论的地方是什么？”
- 不使用 AI 数字人作为主视觉。
- 以旁白、动态文字、来源卡和少量合法素材为主要表达形式。
- 视频长度默认 60–120 秒，竖屏 1080×1920。
- 需要一定内容深度，但避免为了显得深刻而堆砌学科名词。
- 声音可以来自多个来源，系统负责推荐和调用已配置的方式。

## 3. 首版范围

### 3.1 包含

1. 手动触发一次完整生产流程。
2. 从可配置的热点源生成 5–10 张候选选题卡。
3. 针对候选主题建立证据包和风险提示。
4. 两个人工审核点：选题审核和脚本审核。
5. 根据证据选择心理学、经济学、新闻传播学、人文常识等 1–2 个合适视角。
6. 生成 60–120 秒观点型脚本，并将事实性陈述绑定到来源。
7. 依据脚本推荐旁白来源，可直接调用已配置 TTS，也可导出到剪映并回填音频。
8. 自动选择动态文字、来源卡、授权切片或 AI 抽象画面。
9. 生成字幕、配乐建议、竖屏成片和质检报告。
10. 保存所有中间产物，失败后从当前阶段继续。

### 3.2 不包含

- 自动发布到微信视频号。
- 无限制爬取平台评论或绕过登录、验证码、反爬机制。
- 搬运未获授权的影视、综艺、新闻或创作者视频。
- 模仿未授权真人音色。
- AI 数字人和写实人物口型驱动。
- 多账号管理后台。
- 自动用播放数据调整账号策略。

## 4. 核心原则

### 4.1 证据先于观点

脚本可以有立场，但不得用模型补造事实。无法核实的内容必须标成“待核实”“推测”或从脚本中删除。

### 4.2 解释框架不是证据

心理学、经济学、新闻传播学和人文常识用于解释已确认事实之间的关系。学科概念本身不能代替事件证据；生活常识只能帮助理解，不能证明事实。

### 4.3 人工审核锁定版本

选题和脚本分别通过人工审核。脚本通过后生成内容哈希，下游 TTS、字幕和画面规划只能引用锁定稿，不得悄悄改写。

### 4.4 权利不清就降级

素材许可不清时，自动降级为动态文字、来源卡或重新生成的抽象画面。声音授权不清时，自动切换到平台合成音或用户明确授权的声音。

### 4.5 付费调用有预算边界

每个项目记录模型、调用次数和预计费用。任何新供应商首次启用、超出项目预算或可能产生明显费用时，必须在调用前让用户确认。

## 5. 工作流状态机

```text
DISCOVERED
  -> RESEARCHED
  -> TOPIC_REVIEW_REQUIRED
  -> TOPIC_APPROVED
  -> SCRIPT_DRAFTED
  -> SCRIPT_REVIEW_REQUIRED
  -> SCRIPT_APPROVED
  -> VOICE_READY
  -> EDIT_PLAN_READY
  -> RENDERED
  -> QC_PASSED
  -> COMPLETE
```

失败状态不销毁上游产物：

```text
BLOCKED_EVIDENCE
BLOCKED_PERMISSION
BLOCKED_PROVIDER
FAILED_RENDER
FAILED_QC
```

每次状态变化都写入 `workflow-events.jsonl`，包含时间、输入哈希、输出哈希、供应商、费用和错误摘要。

## 6. 模块设计

### 6.1 热点发现模块

**输入：** 时间窗口、内容赛道、排除词、候选数量。

**输出：** `topic-candidates.json`。

候选卡至少包含：

- 原始标题和规范化主题。
- 来源、发布时间、热度信号。
- 可形成的问题钩子。
- 受众关联度、讨论空间、证据可得性、时效性。
- 法律、隐私、名誉、未成年人和版权风险。
- 是否适合当前账号定位。

首版允许数据源：公开 RSS/API、站点公开榜单、用户提供的链接或文本、合规搜索结果。平台评论采集只在公开可访问且条款允许时启用。

### 6.2 证据研究模块

**输入：** 选题候选。

**输出：** `sources.json` 和 `research-brief.md`。

来源按用途分类：

| 类型 | 作用 | 默认权重 |
|---|---|---|
| 当事人或机构一手材料 | 确认原始事实和表态 | 高 |
| 官方数据、公开记录、论文 | 支撑事实或机制 | 高 |
| 专业媒体的原始报道 | 补充采访和时间线 | 中高 |
| 专家解释或评论 | 提供解释框架 | 中 |
| 平台评论样本 | 观察公众问题和情绪 | 低，不证明事实 |
| 生活常识 | 帮助解释 | 不计入证据等级 |

研究简报必须明确：已确认事实、来源冲突、未知信息、可用解释视角、反证或边界、发布风险。

### 6.3 选题决策与审核 A

评分维度采用 0–5 分：

- 受众关联度。
- 问题张力。
- 证据充分度。
- 可形成独立判断的空间。
- 账号定位匹配度。
- 视觉实现难度（反向评分）。
- 风险（反向评分）。

系统推荐前三名，但不自动确定题目。用户可以批准、驳回或要求补充证据。

### 6.4 脚本模块

脚本采用以下结构，不要求每段等长：

1. **问题钩子：** 提出真正需要回答的问题，避免先下结论。
2. **事实基线：** 用最少句子交代已确认事实。
3. **有力证据：** 展示能改变判断的事实、数据、原始材料或可靠报道。
4. **机制解释：** 从最合适的 1–2 个学科视角解释“为什么”。
5. **反证与边界：** 说明另一种可能、证据局限或常见误解。
6. **独立判断：** 给出可辩论、不过度延伸的结论。
7. **收束问题：** 邀请讨论，不制造虚假二选一。

每个句子标记为：

- `fact`：必须绑定一个或多个来源。
- `attribution`：必须准确指明谁说了什么。
- `analysis`：必须能追溯到前面的事实。
- `opinion`：明确表达为判断，不冒充事实。
- `transition`：只负责结构衔接。

### 6.5 脚本审核 B

审核界面必须同时展示：

- 完整脚本。
- 每个事实句的来源。
- 未解决的证据冲突。
- 使用的学科视角及其适用边界。
- 预计时长、敏感词和风险提示。

批准后生成 `approved-script.json` 和 SHA-256 哈希。下游只接受该文件。

### 6.6 旁白模块

旁白严格根据锁定文案生成，不主动改写语气或态度。默认推荐自然、克制、信息型声音。

供应方式按能力注册，不设置永久唯一优先级：

1. 已配置的云端 TTS。
2. 已安装并可调用的本地 TTS 模型。
3. 用户已授权的真人录音或音色模型。
4. 剪映 AI 语音：导出文案，用户生成后回填音频。
5. 用户提供的外部音频。

输出：

- `voice/master.wav`。
- `voice/word-timings.json`。
- `voice/voice-report.json`。

报告记录供应商、模型、音色、授权依据、脚本哈希、时长、响度和费用。

### 6.7 声画决策模块

逐场景选择画面类型：

| 场景信息 | 首选画面 |
|---|---|
| 核心问题、转折、判断 | 动态大字 |
| 数据、报道、公开记录 | 来源卡、图表或局部高亮 |
| 必须呈现真实动作且已有许可 | 授权切片 |
| 抽象概念、氛围过渡 | AI 抽象画面或简单动效 |
| 权利不清或证据不足 | 动态文字 |

首版整体节奏以旁白为主。画面不需要逐句“配图”，而要帮助理解、证明来源或维持节奏。

### 6.8 配乐决策

- 严肃、争议、事实密集内容：默认无配乐或极弱环境音乐。
- 生活思考和情绪收束：可用低存在感氛围音乐。
- 配乐必须有明确许可记录。
- 旁白出现时，音乐目标响度比旁白低至少 16 dB；最终值由实际混音质检决定。

### 6.9 渲染与质检模块

默认渲染目标：H.264 MP4、1080×1920、30 fps、AAC 音频。

质检至少覆盖：

- 视频时长 60–120 秒。
- 旁白脚本哈希与锁定稿一致。
- 字幕无超框，关键文字处于安全区。
- 音频无明显削波，旁白清晰可懂。
- 所有事实句都能解析到来源。
- 所有素材和音乐都有许可或生成记录。
- 无来源冲突被静默忽略。

失败时生成 `reports/qc.json`，只重跑失败阶段。

## 7. 每条视频的产物结构

```text
projects/<topic-id>/
├─ project.json
├─ topic-candidates.json
├─ topic-card.json
├─ sources.json
├─ research-brief.md
├─ script-draft.json
├─ approved-script.json
├─ workflow-events.jsonl
├─ voice/
│  ├─ master.wav
│  ├─ word-timings.json
│  └─ voice-report.json
├─ assets/
│  └─ manifest.json
├─ edit-plan.json
├─ output/
│  └─ final.mp4
└─ reports/
   └─ qc.json
```

所有 JSON 文件使用版本字段 `schemaVersion`。首版为 `1`。

## 8. 供应商与适配器边界

统一注册表从环境变量和本地配置中发现能力：

- `TopicSourceAdapter`：获取热点候选。
- `SearchAdapter`：获取公开搜索结果。
- `LanguageModelAdapter`：研究整理和脚本生成。
- `TtsAdapter`：生成旁白和时间信息。
- `AssetAdapter`：获取授权素材或生成 AI 画面。
- `Renderer`：根据 `edit-plan.json` 生成 MP4。

适配器不得绕过工作流审核，也不得直接改写锁定产物。

## 9. Skill 的触发与交互约定

建议的前置描述：

```yaml
name: short-video-opinion-workflow
description: Use when producing evidence-backed Chinese opinion short videos from topic discovery through narration, visual planning, rendering, and quality review.
```

典型触发请求：

- “帮我找今天适合做观点视频的话题。”
- “基于这个事件做一条有证据的 90 秒视频。”
- “继续上次已经审核脚本的项目并生成旁白。”
- “这段文案更适合动态文字、切片还是 AI 画面？”

Skill 读取当前项目状态，只执行下一个合法阶段；遇到两个审核点、付费边界、授权不清或事实不足时停止并说明原因。

## 10. 合规与安全边界

- 不采集登录后数据，除非用户明确授权且平台规则允许。
- 不绕过验证码、付费墙、反爬或访问控制。
- 评论只作为观点样本，不公开普通用户的可识别信息。
- 涉及真实人物的负面判断，必须区分事实、指控、回应和作者观点。
- 未成年人、医疗、法律、投资和公共安全主题默认提高风险等级。
- 任何克隆音色必须记录权利人授权。
- 发布前必须由用户人工确认；首版不自动发布。

## 12. MVP 验收标准

首版通过需要满足以下条件：

1. 从一次手动命令生成至少 5 张候选选题卡。
2. 用户批准一个选题后生成带来源的研究简报。
3. 生成并人工批准一份 60–120 秒脚本。
4. 每个事实句至少绑定一个来源，或明确标成无法核实并被质检拦截。
5. 至少支持一种可直接调用的 TTS 和剪映人工回填路径。
6. 自动生成 `edit-plan.json`，主要使用动态文字和来源卡。
7. 渲染 1080×1920 MP4，并生成字幕、素材许可清单和质检报告。
8. 在 TTS 或渲染失败后，不需要重新执行已经通过的研究和脚本审核。
9. 付费调用、素材许可、音色授权和模型版本均可追溯。
